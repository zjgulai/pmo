## 第一步：项目核心能力剖析

### 1.1 核心能力（安身立命之本）

| # | 核心能力 | 本质上解决了什么 |
|---|----------|------------------|
| C1 | **双平台融合选品引擎（Fusion）** | 用量化算法（SHI × CVI × OppScore）将"社媒热度"与"电商销售力"两个维度合并为一个可排序的机会分，**解决了选品团队凭经验拍脑袋、无法在两个平台间系统比对的问题** |
| C2 | **VOC 评论洞察分析** | 将 Amazon 真实用户评论分解为情感维度、议题标签、高亮词云，**解决了卖家"只看星级不懂用户为什么差评"的表面分析困境** |
| C3 | **Playwright 实时数据采集管道** | 以爬虫模拟人工采集 Amazon Best Sellers 榜单与产品详情，**解决了"第三方数据工具贵、更新频率低、字段不够用"的数据供给痛点** |
| C4 | **四层数仓架构（ODS → DWD → DWS → ADS）** | 80+ 张表覆盖原始层到应用层，支持 Excel 批量导入与自动 ETL 清洗，**解决了数据杂乱无章、无法沉淀历史对比的数据治理缺失** |
| C5 | **可编程指标计算引擎** | fusion-engine.ts 以权重系数驱动 SHI/CVI/OppScore 全量计算，每个维度均可配置和分解，**解决了"评分黑盒、无法解释给团队"的信任问题** |

### 1.2 拓展能力（可延展的潜力）

| # | 拓展能力 | 本质上解决了什么 |
|---|----------|------------------|
| E1 | **多源 Excel 标准化导入（DataManager）** | 通过字段别名映射引擎，任意第三方平台（蝉妈妈/Jungle Scout）的导出文件均可接入，**解决了数据孤岛、人工手工整理 Excel 的低效问题** |
| E2 | **LLM 报告自动生成（框架就绪，待接 API）** | UI 骨架和数据快照已完整，接入 Claude/GPT 即可生成结构化选品报告，**解决了"分析师整理报告要 2 天"的人力成本问题** |
| E3 | **双端部署（静态 GitHub Pages + 腾讯云 HTTPS）** | Mock Link 使前端可独立演示，**解决了"向客户演示需要本地环境"的展示门槛** |
| E4 | **23 个功能页面 + 38 个 tRPC 接口** | 覆盖 TikTok 全链路（商品/达人/小店/视频/直播）+ Amazon 全链路（榜单/关键词/评论/品牌），**解决了多工具切换、数据不统一的割裂体验** |
| E5 | **概念管理体系（productConcepts）** | 以"选品概念"为粒度绑定 TikTok 和 Amazon 关键词，**解决了品类研究无法沉淀、下次重新分析的知识浪费** |

## 第二步：从能力倒推三层问题（价值金字塔）

```
┌────────────────────────────────────────────────────────────┐
│  🔴 宏观·战略层                                             │
│  增长曲线 × 护城河 × 规模化复制                              │
│  "要开哪个新品类？平台要怎么布局？"                           │
├────────────────────────────────────────────────────────────┤
│  🟡 中观·管理层                                             │
│  数据决策 × 团队协同 × 资源调配                              │
│  "选品会要看什么数据？哪个 BD 跟哪个品类？"                   │
├────────────────────────────────────────────────────────────┤
│  🟢 微观·执行层                                             │
│  操作效率 × 重复劳动 × 易错环节                              │
│  "今天要查哪些 ASIN？评论分析怎么做？"                        │
└────────────────────────────────────────────────────────────┘
```

### 🟢 微观·执行层：一线业务执行者的痛点

基于 **C3（爬虫采集）+ C2（VOC 分析）+ E4（全链路页面）** 倒推：

1. **痛点 M1 — 每日手工查榜单**：选品专员每天打开多个平台，手工截图或复制数据，最终整理进 Excel，耗时 2~3 小时/天。
2. **痛点 M2 — 评论分析靠人读**：一个产品 500+ 条英文评论，人工分类情感和议题需要 4~8 小时，且结论因人而异。
3. **痛点 M3 — TikTok 趋势要人跟**：需要每天刷 TikTok 才能感知到某个品类视频开始爆发，无任何系统化监控。

### 🟡 中观·管理层：中层决策者的决策困境

基于 **C1（Fusion 引擎）+ C4（数仓）+ E5（概念管理）** 倒推：

1. **痛点 MD1 — 选品会数据各说各话**：不同人从蝉妈妈、Jungle Scout 抓取的数据口径不一，同一个品类在会议室里出现三个不同的"月销量"。
2. **痛点 MD2 — 无法量化"哪个机会更好"**：选品要不要做，全凭老板感觉和经验，无法说清"为什么选 A 不选 B"。
3. **痛点 MD3 — 数据不沉淀，下次重新做**：每次选品分析结果只存在 PPT 里，下个季度选品要从头再来。

### 🔴 宏观·战略层：公司级商业问题

基于 **C1 + C4 + E1 + E2** 倒推：

1. **痛点 ST1 — 新品类进入时机判断凭感觉**：公司在研究"要不要做户外宠物品类"时，无法获取客观的市场验证数据，决策风险高。
2. **痛点 ST2 — 多地区多站点选品能力无法复制**：US 站选品经验无法快速平移到 DE/UK/JP 站，缺乏标准化工具和数据体系。
3. **痛点 ST3 — 供应链决策滞后市场信号**：爆款起来了才开始备货，往往已经错过了黄金期前 4~6 周的时间窗口。

## 结语：项目不可替代的存在意义

> **这个项目本质上是在做一件事：把"人脑经验驱动"的跨境选品决策，升级为"数据+算法驱动"的可复现、可量化、可扩展的系统能力。**

当前行业现状：90% 的跨境出海团队仍依赖人工盯榜 + 主观判断 + 割裂工具组合（蝉妈妈看趋势、Jungle Scout 查市场、人工读评论、Excel 汇总）。这意味着：
- **人力成本高**：1 个高级选品分析师市场价 20~35 万/年，且无法规模化
- **决策时效差**：从发现机会到形成结论至少 1~2 周，远慢于市场变化速度
- **经验无法沉淀**：人离职，选品知识体系就消失了

**本项目是当前团队将这一能力"固化为数字资产"的唯一载体。**

当前最关键的一步投入是：**打通 ETL Pipeline + 接入 LLM 报告生成（合计 5~6 周，1~2 名工程师）**，届时即可实现"导入 Excel → 自动计算机会分 → AI 生成报告"的完整闭环，**产品将从"好看的演示系统"蜕变为"每天创造决策价值的生产工具"**。
